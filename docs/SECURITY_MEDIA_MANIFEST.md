## Discovered boundaries

- `src/features/media/media.routes.js`: POST `/api/media/upload`, multipart field `file`; protect + requireOnboarding + uploadLimiter + multer memory storage. One file, 25 MiB maximum, MIME allowlist and application/octet-stream filename-extension exception. Claimed MIME and original extension are client inputs; byte-signature validation is not present in local saving.
- `media.controller.js`, `utils/localMediaStorage.js`: context message/avatar uses caller-specific messages/avatars folder; handoff uses shared medcollab/handoffs. Unknown context falls back to message. Local randomized basename retains original extension; URL derives from API_BASE_URL. No media ownership database/model or resource-space association is created.
- Configured Cloudinary uses server credentials, upload_stream, image or raw(PDF), shared handoff folder; no direct signed-upload API discovered. Image thumbnail transforms and PDF attachment URLs differ from local behavior. Cloudinary decoding/rejection remains UNKNOWN in this batch.
- DELETE `/api/media/:publicId`: Express parameter then explicit decodeURIComponent; ownership is a string contains check for `/messages/<caller>/` or `/avatars/<caller>/`. Local deletion calls path.join then unlinkSync without canonical-root enforcement. Cloudinary tries image then raw destroy. Handoff-context upload has no owner path that passes deletion check. No media-update route found.
- GET `/uploads/*`: express.static without authentication, outside explicit route count. Public access is implemented; intended confidentiality, URL revocation/cache policy are UNKNOWN.
- Message POST and reply accept content.mediaUrl. `sendMessage` permits cloudinary.com/res.cloudinary.com and subdomains by hostname; it does not bind cloud name, owner, publicId or scheme. Local upload URLs fail this allowlist. thumbnailUrl and other content metadata are schema inputs. PUT message edits text only, not media replacement.
- `handoff.model.js` patients[].attachments[] holds url, thumbnailUrl, fileName, mimeType, uploadedAt; POST handoffs and sender-only draft PUT accept patients. User PUT `/api/users/me` allows avatarUrl. These are separate reference sinks, not media upload authorization.
