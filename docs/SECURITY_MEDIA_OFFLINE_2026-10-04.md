# Local media storage and offline Cloudinary SDK contracts

Implementation phase, initially pending hosted validation. Follow [AGENTS.md](../AGENTS.md). No application fix, Cloudinary credential or real integration is included. Existing 691 IDs/expectations stay frozen; the general API workflow is not rerun by this phase.

Dedicated workflow: `.github/workflows/vocle-media-security.yml`. Dedicated runner: `medcollab-backend/scripts/security-media/run.js`. It selects the existing 37 media/cross-module cases unchanged and appends **26 local cases VOCLE-692–717** and **34 SDK contract cases VOCLE-718–751**. Combined registered security catalog: **751**. This workflow executes 97 selected cases, not all 751. Historical 691-case results and route coverage remain separate evidence.

Local cases use real multipart HTTP, unchanged Express/auth/controllers/models, actual disposable MongoDB and scratch files. They add upload identity lifecycle, avatar canonical ownership, duplicate/unsafe names, unsupported/malformed types, octet-video metadata, handoff ownership/lifecycle, profile partial failure, duplicate/stale references and URL/metadata sinks. Characterization cases explicitly retain unknown sharing/retention policy rather than inventing an ownership rule.

Contract cases replace `require('cloudinary')` at the SDK boundary, execute the real upload/delete routes and record exact stream bytes/hash/options, destroy calls and URL-builder options. No actual SDK client is loaded. Because actual configuration correctly returns unconfigured with no credentials, a **test-only exported configuration-predicate override** selects the cloud branch; it does not fabricate credentials or mock authorization/business logic. Readiness and every IPC state snapshot verify the injected object and absence of real SDK modules. Calls and simulated assets are labeled as simulation, never provider storage/deletion evidence.

Coverage includes image/video/raw PDF versus octet dispatch, caller folders/forged options, filename metadata, unique-name intent, explicit overwrite prevention, exact thumbnail/PDF builder parameters, builder/callback failures, image/raw/video deletion dispatch, invalidation, handoff deletion, embedded-owner namespace requests, upload→message persistence, video-message compatibility and source lifecycle hooks. The SDK double performs no byte decoding or Cloudinary path normalization. Image/raw destroy fallback and simulated not-found outcomes exercise application branches only.

Safety has two layers. Node guards reject non-loopback sockets/DNS/HTTPS/fetch, unexpected ports and redirects before I/O; a separate strict offline self-test proves rejection of provider/proxy variables, credential files, cleanup escape and six intercepted networking probes. Hosted tests run in a container sharing MongoDB's **Docker `--network none` namespace**; runtime asserts that only `lo` exists and there are no external routes. No secrets are passed into the container. Backend/runner use exact loopback API and `vocle_ci`; every case restarts the backend, resets synthetic fixtures, confirms real test-only OTP identity and waits for settled state. Backend logs and raw bodies/tokens are discarded. Source fingerprint and cleanup failures block execution, while actual application differences remain observations.

Fixture evidence is synthetic only: fixed PNG, authored one-page PDF, one-frame black MP4. No malicious/real content, clinical data or downloaded media. The initial workflow authors the tiny MP4 offline with FFmpeg; successful artifact retention allows versioning those exact bytes for deterministic future runs. Video/PDF provider decoding, derived-delivery success and real remote naming/deletion remain unproven even with valid fixtures.

Reports: `results.json`, `summary.md`, `security-test-report.md`, `manifest.json` and the synthetic video fixture, under artifact `vocle-offline-media-security`. Results include unchanged-state checks, filesystem hashes/existence, exact SDK calls, simulated state and SDK/network assertions. Infrastructure failures distinguish missing controls, IPC/backend/fixture/transport errors and incomplete cleanup from observations. Frozen manifest checks protect the original 691 and all new stable IDs.

Stage 3 remains disabled: real decoder behavior, provider public IDs/collisions/folder modes, actual permissions/presets/delivery protections, raw-PDF preview delivery, CDN cache invalidation and remote lifecycle reconciliation require a separately approved synthetic-only account and the guarded broker/attestation described in [the design](SECURITY_CLOUDINARY_MEDIA_DESIGN_2026-10-04.md). Replacing an SDK and recording valid option intent cannot prove any of these. The current predicate seam and simulated URLs must not be reused as live credentials or evidence.
